# kayhardam.dev

Kay Hardam's personal site, https://kayhardam.dev: a static Astro 7 site in Dutch (`/`) and English (`/en/`). Since the palette "Hars" (Kay, 15 November 2026) it is a portfolio for front-end jobs at agencies, with one goal: a conversation. The button "Plan een gesprek" (a `mailto:` to `hallo@kayhardam.dev`) is in the header and the close. Few words: the board tells the story. `CLAUDE.md` is a symlink to this file.

Everything in `docs/` stays local and is not in the repo: the build brief (`docs/kayhardam-dev-brief.md`), the plan per phase and the status. The one exception is `docs/metingen.md` (`.gitignore`: `docs/*` with one exception). The brief holds the agreed texts, the design and the phases; the Hars rebuild follows Kay's brief of 15 November 2026 (in the session, not in `docs/`).

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Dev server on port **4322** (not 4321: Coachboard's may run at the same time). |
| `npm run verify` | What CI runs (`.github/workflows/ci.yml`, on pull requests and pushes to `main`): `astro check` and `svelte-check --fail-on-warnings` → `vitest run` → `astro build` → `node scripts/check-links.mjs` → `node scripts/check-budget.mjs`. Must be green before every commit. |
| `npm run budget` | The size budgets against the current `dist/` (run `npm run build` first). |
| `npm run e2e` | End-to-end tests (Playwright) in mobile Chromium and WebKit. Builds, then serves `dist/` with `wrangler dev` on port **8788** (not 8787: Coachboard's e2e tests may run at the same time). A separate CI job, not part of `verify`. First time: `npx playwright install chromium webkit`. |
| `E2E_BASE_URL=https://<url> npx playwright test e2e/security.spec.ts` | An e2e file against a deployed site (a preview URL, or production: `https://kayhardam.dev`) instead of `wrangler dev`. Run `npm run build` on that commit first: the page list comes from `dist/`. |
| `node scripts/measure-coachboard.mjs <url>` | The touch targets of Coachboard's editor, for the lens: `src/data/tap-targets.json` and the screenshots `src/assets/coachboard-editor-{nl,en}.png`. Against Coachboard built at commit `03be23b` and served with `wrangler dev` (the script's header says how, in a worktree of its own). Run it again only for a newer Coachboard, and change `COMMIT` with it; `tap-targets.test.ts` checks the file is that commit's. |
| `npm run build && node scripts/og-image.mjs` | The share image `public/og.png`, with Playwright's Chromium (on the Mac); then commit it. Still the phase-10 image (the photo, the KH logo, ink blue): making it in Hars is open. |
| `node scripts/favicons.mjs` | `public/favicon.ico` and `public/apple-touch-icon.png` from `public/favicon.svg`, with sharp; then commit them, and make `og.png` again. Still phase 10's ink-blue player; Hars is open. |
| `node scripts/clean-photo.mjs "screenshots/foto/<original>.jpg" src/assets/kay-hardam.jpg` | The clean copy of the photo, on the Mac. Since Hars the page has no photo; the copy stays for `og.png`. |

Commit only when `npm run verify` exits with code 0. Check the exit code itself, not the output: a pipe through `tail` or `head` hides a failure. Always run verify and the commit as one command, joined with `&&`, for example `npm run verify && git commit -m "…"`: then a red verify never makes a commit.

## Way of working

- One branch and one pull request per phase (`fase-N-<name>`; the Hars rebuild is on `ccr-564779e8-91b6g5`, the branch its session was allowed to push to). Kay merges after his own check, with a plain merge.
- No attribution to Claude in this repo: no Co-Authored-By line in commits and no "Generated with Claude Code" in pull requests (Kay, 17 October 2026). `.claude/settings.json` turns it off for this project only; Coachboard keeps it.
- Never `git add -A` or `git add .`: add files by name. A new local folder (screenshots, measurements, scratch files) goes in `.gitignore` first, before anything is added (Kay, 18 October 2026: screenshots ended up in PR #3 that way).
- Claude Code never deploys. Cloudflare Workers Builds deploys `main` after a merge and gives every branch a preview URL.
- Texts come word for word from Kay. A new or changed text is agreed with Kay first; a missing text is asked for, never made up. A text Claude had to propose is marked as a proposal in `nl.ts` or `en.ts` until Kay agrees (now: the lens's label, keys and image alt, and all English texts of the Hars parts).
- Measurements (sizes, Lighthouse) go in `docs/metingen.md`, per phase. Lighthouse runs twice: simulated and with `--throttling-method=devtools`.

## Structure

- `README.md` is for visitors on GitHub, in English: what the site is and how it is made. A change to it is agreed with Kay first, like the other texts. It still says "one Svelte island": there are three now (open, for Kay).
- `LICENSE`: MIT, "Copyright (c) 2026 Kay Hardam", for the code. The texts, the logo and the photo are not part of it (the README says so).
- `.node-version` holds `22`, the Node version for Workers Builds and local work; CI sets 22 in `.github/workflows/ci.yml`. Change both together.
- `src/pages/index.astro` (Dutch) and `src/pages/en/index.astro` render `src/components/Home.astro`; the language comes from `Astro.currentLocale`.
- `src/pages/404.astro` is one page for every missing URL, Dutch first, then English, with the Dutch title, in Hars. `wrangler.jsonc` serves it with status 404.
- Texts: `src/i18n/nl.ts` and `src/i18n/en.ts` (the type comes from `nl.ts`, so a text missing in English fails `astro check`); `text(locale)` in `src/i18n/index.ts`.
  - `board.counter` ("Stap {n}/{count}") is the visible counter, `board.step` the one for screen readers, `board.steps` the step lines' list name, `board.kinds` the text per kind of arrow (a kind without a text stops the build), `board.ball` the ball's label. `hero.button` is the link to Coachboard.
  - `figures` is a list of three: `value`, `rest`, `was`; `lens` holds `heading`, `target` (with `{name}`), `hint`, `label`, `keys`, `image`; `work.heading` and `work.items` (`name`, `status`, `tech`); `talk` the button; `close.heading`.
  - No job title on the page: `texts.test.ts` allows one only in `title`, `description` and `jobTitle` (the JSON-LD), which keep "Gymleraar en handbaltrainer".
  - The first mention of Coachboard on a page is "Handball Coachboard" (the description); after it "Coachboard".
- `src/data/links.ts`: `coachboard` (per language), `coachboardSite` (for `sameAs`), `github` (for `sameAs` only now), `evidence` (the three figures' links), `email` and `mailto`.
- `src/lib/coords.ts`: a place on the court in metres, "[8,5; 8,7]" in Dutch and "[8.5, 8.7]" in English, for the step lines and the ball's label.
- `src/layouts/BaseLayout.astro`: `lang`, canonical, hreflang (nl, en, and x-default to `/en/`, Kay's choice), the fonts (Fontsource's CSS for the six weights, `font-display: swap`) and the preload of Barlow Condensed 800, `theme-color` espresso (a `<meta>` can't read a token, so the one hex value outside `tokens.css`), the description and Open Graph (`og:title` and `og:description` are the title and the description; `og:image` is `/og.png`, one for both languages, with `og:image:alt`), and a JSON-LD Person (`name`, `jobTitle`, `url` the canonical, `sameAs` GitHub and `https://handballcoachboard.com/`). The 404 page is `noindex`, without canonical, hreflang, description, Open Graph or JSON-LD.
- `@astrojs/sitemap` (`astro.config.mjs`) writes `sitemap-index.xml` and `sitemap-0.xml` with `/` and `/en/`, each with hreflang nl and en; it leaves the 404 out by itself. `src/pages/robots.txt.ts` points to it. Both after Coachboard (commit `88a58a4`).
- The share image `public/og.png` and the favicons are still phase 10's (the photo, the ink-blue KH player, Plus Jakarta Sans as paths and in `og-image.mjs`); the scripts and their tests describe that state. Making them in Hars is open. `check-budget.mjs` has budgets for them, raw.
- The photo `src/assets/kay-hardam.jpg` stays only for `og.png`: clean, square, without metadata (`src/assets/photo.test.ts`); `scripts/clean-photo.mjs` makes it from the original in `screenshots/foto/`, outside git.
- Styles: `src/styles/tokens.css` (the eight colours of Hars, the focus ring's sizes, the three fonts, the 18 px text, `--container`, `--gutter`, `--tap`, `--header`; the breakpoints 560 and 860 px are literal) and `src/styles/base.css` (the ground espresso, room text in Barlow 500, the focus ring, `.container`, `.visually-hidden`).
- The board in the hero (`src/components/board/`):
  - `src/data/boards.ts` holds the two Coachboard share links, the contract for the board. Dutch is Kay's attack "Kruising AI–IK" (the sentences "AI verkent." / "Ik kies." / "AI bouwt." / "Ik controleer."); English is still the brief's "Crossing CB–LB", the same attack with other words, until Kay makes the English link. `boardFrom()` decodes a link at build time with Coachboard's `decode()`; `stepsFor()` makes the step lines. A broken link, a link without a title, a step without exactly one arrow or a kind without a text stops the build. A new link is made with `encode()` from the copy of `format.ts`, which is Coachboard's.
  - `Board.astro` decodes the link and makes the step lines; `BoardCard.svelte` draws the hero (the text column and the court); `Court.svelte` draws the court.
  - `BoardCard.svelte` is an island (`client:visible`). It gets the decoded board as props, so the browser never decodes the link. On the server and in its first render it is the hero without JavaScript (step 1, the buttons `disabled`, the link working), so hydrating changes no element. Once mounted it plays by itself in a loop, except with reduced motion; it pauses out of view and in a hidden tab. The playing (`advance()`, `play()`, `stop()`, `sync()`, the timing of `viewer.ts`, `HOLD` 2.6 s) is phase 5's, unchanged; the step lines take the place of Previous and Next: the next step's line plays its move, any other goes there at once. `aria-live` on the sentence is `off` while it plays by itself and `polite` once it stands still (Kay's decision, phase 5), set before the sentence changes, with Svelte's `tick()` in between; the sentence is `aria-atomic`. `e2e/play.spec.ts` tests all of it with Playwright's clock.
  - The ball's label and the ring in room around the ball are layers of `BoardCard.svelte` over the court: SVG attributes placed in percent, never a `style` attribute (the CSP). The ball's edge alone (espresso) is 2.7:1 in the goal area; with the ring 7.9:1.
  - The styles are in `board.css`, global, every rule under `.board`. The court in Hars comes from CSS only: `Court.svelte` sets its colours as attributes, a CSS rule beats an attribute, so `board.css` picks each of Coachboard's colours by its attribute (`[fill="#15803d"]`) and gives it its token. Those hex values are selectors, not colours. Nothing in the hero changes its size while it plays or when the fonts come: the court has a fixed ratio, the sentence two lines (three for a longer one), the step lines fixed columns in em (where the arrow starts 7.7em, where it goes at least 7.2em: one line up to a fallback font 6% wider); `e2e/board-box.spec.ts` and `e2e/art.spec.ts` check it.

## Rules

- **Trailing slash everywhere** (`trailingSlash: "always"`). Build links with `getRelativeLocaleUrl()` from `astro:i18n`.
- **No JavaScript on the page except the three islands**, `BoardCard`, `Figures` and `Lens`, each Svelte 5 with `client:visible`, at most once on a page, plus Astro's two inline scripts for them. `scripts/check-budget.mjs` fails on another island or directive, the same island twice, an island on the 404 page, an inline `<script>` without an island, any `<script src>` and any modulepreload. Its JS budget counts the islands' files and what they import (gzip); lazy JS has a budget of 0. The JSON-LD is a data block, not JavaScript: `check-budget.mjs` allows it. Without JavaScript the page is complete: step 1 on the court, the figures on their final values, the lens on the smallest target, every link working.
- **CSP:** everything `'self'`. Astro writes the `<meta>` with hashes for its inline scripts and styles (`security.csp` in `astro.config.mjs`); `public/_headers` has `frame-ancestors 'none'` and the other security headers. Nothing loads from another origin: `e2e/security.spec.ts` checks every page. No `style` attribute, also not from Svelte (`style:`): the CSP blocks it. Anything that moves is an SVG attribute.
- **Images:** only through `astro:assets` from `src/assets/`, never in `public/` (the one exception is the photo inside `og.png`). The lens's screenshot has `aspect-ratio` in the CSS and `width`/`height`, so nothing moves while it loads (and WebKit doesn't collapse a failed image). `check-budget.mjs` measures every file in a `src` or `srcset`, with a budget per format, and fails on a missing one (`check-links.mjs` doesn't read `srcset`).
- **Colour: the palette Hars**, eight custom properties in `tokens.css` and nothing else, except transparencies of these eight (`color-mix(in srgb, var(--room) 16%, transparent)`): `--espresso #16110d` (the ground, text on amber, defenders, the goal), `--walnoot-donker #261b12` (the hero), `--walnoot #4a3421` (the court), `--walnoot-licht #63472d` (the goal area), `--amber #ffb300` (the accent: the button, the figures, the active step, attackers), `--room #fff6e8` (text, the court's lines, arrows, the players' edges), `--zand #d3c4b0` (secondary text), `--gloed #ff5a2b` (only the ball, with an edge in espresso). `src/styles/colours.test.ts` fails on a loose hex value anywhere, with the four reasons it allows (the tokens, `Court.svelte`'s copy, `board.css`'s selectors, `theme-color`); `tokens.test.ts` checks the eight values and the contrasts the page relies on (text 4.5:1, lines 3:1). Colour is never the only sign: every attacker and the keeper have a label, the ball has its label beside it, a status is a word.
- **Fonts:** Barlow Condensed 700/800 (headings, figures, the name, the sentence, the players' labels, in capitals), Barlow 500/600 (running text, 18 px) and JetBrains Mono 400/700 (the step lines, the measures, the language switch), Latin only, self-hosted through `@fontsource/barlow-condensed`, `@fontsource/barlow` and `@fontsource/jetbrains-mono`, `font-display: swap`. The arrow `→` is not in JetBrains Mono's Latin subset: the step lines draw it as an SVG. The board no longer uses `system-ui`.
- **Accessibility, WCAG 2.2 AA:** links and buttons at least 44 × 44 px (`e2e/a11y.spec.ts`, and `e2e/narrow.spec.ts` for the step lines' 48 px); the focus ring 3 px amber, 2 px out, with an espresso edge around it (a `box-shadow` of 7 px in `base.css`; a component's own edge is a `border`, never a shadow, or it hides the ring's edge); axe without findings at rest and while the board plays (`e2e/play.spec.ts`). With a reader's own text spacing (WCAG 1.4.12) no part of a step line covers another: a place wraps inside its own column and the line grows (`e2e/spacing.spec.ts`). The sticky header never covers what has the focus (WCAG 2.4.11): `scroll-padding-top` on `html` is `--header` plus 16 px, and `e2e/a11y.spec.ts` tabs forward and back to check it. `prefers-reduced-motion`: nothing plays by itself, the figures stand on their final values, the step lines jump without a move. No horizontal scroll from 320 to 1440 px (`e2e/narrow.spec.ts`, `e2e/board.spec.ts`). The language switch has one place per width (`display: none` at the other), so a keyboard meets it once.
- **No new dependencies without Kay.** The three font packages replaced `@fontsource/plus-jakarta-sans` with his agreement (15 November 2026).
- **Hosting:** `wrangler.jsonc` serves `dist/` as static assets, on Worker `kayhardam-site`.
  - Workers Builds makes the images at the build, with sharp. sharp is in `devDependencies` and an optional dependency of Astro: don't remove it, and never install with `--omit=optional`. Without sharp the build fails (`MissingSharp`), and nothing deploys.
  - Its `routes` entry attaches `kayhardam.dev` as a Custom Domain (phase 6). Keep it there and don't manage the domain only in the dashboard: a deploy whose config lacks it removes the domain again.
  - The deploy takes a domain over from another Worker without asking: Workers Builds runs wrangler without a terminal. That is how `kayhardam.dev` moved from Worker `kayhardam-dev` (the placeholder) at the launch. `wrangler preview` publishes no routes, so a branch never touches the domain.
  - `workers_dev` stays `false` and `preview_urls` `true`: no workers.dev address, a preview URL per branch.
  - Worker `kayhardam-dev`, the placeholder, is gone: Kay deleted it after the production checks of phase 6 (21 October 2026). There is no way back to it.
  - **Set in the Cloudflare dashboard**, not in this repo:
    - Always Use HTTPS on;
    - Email Address Obfuscation off, so Cloudflare doesn't rewrite the email address or inject a script the CSP would block;
    - Web Analytics off: no statistics (Kay), and an injected beacon would land above the CSP `<meta>`;
    - www: a DNS record `AAAA www 100::` (proxied) and a Redirect Rule to the bare domain, keeping the path and the query (a Custom Domain matches one exact hostname);
    - Email Routing forwards `hallo@kayhardam.dev` to Kay's own address;
    - if Kay turns on Google Search Console: leave its TXT record, or the verification lapses.
- Code taken from Coachboard says so in a comment at the top, with the commit. Take it with `git show <commit>:<path>` in the Coachboard repo, never from its working tree: another session may be working there. The same for measuring Coachboard: a worktree of its own at the commit.
- **The copies from Coachboard stay unchanged** (commit `4ceafd4`): `Court.svelte` (one change: the optional prop `viewBox`), `src/lib/board/{format,geometry,moves,play,viewer}.ts`, `src/lib/viewerIcons.ts`, the tests `geometry.test.ts` and `moves.test.ts`, and `svelte.config.js`. `src/lib/board/edit.ts` has only the type `Selection`. `src/lib/coachboard.test.ts` compares each copy's SHA-256 with the original. To take a newer version, copy it again with `git show` and update the hash and the commit. Hars never touched them: the court's colours come from `board.css`.
